# Technical glossary and retention program

## Training protocol
For each lesson, extract essential terms from the actual lesson and distinguish supplemental concepts. Learn acronym expansion, plain-language definition, technical meaning, practical example, common misconception and interview usage. Start with 5–10 essential terms, expand as appropriate. Review through unaided recall, scenario questions, teach-back, and hands-on application. Revisit after 1, 3, 7, 14 and 30 days during available sessions; missed reviews roll forward. Include cumulative weekly checks and periodic mock interviews. Track private proficiency separately: introduced, recognized, recalled, applied, independently explained. Correct errors and retest without hints before claiming mastery. Keep personal scores private.

## LAB-001 starter glossary
| Term | Meaning and application |
|---|---|
| CPU | Central processing unit; executes instructions. High utilization during a workload may indicate compute pressure. |
| RAM | Random access memory; working memory for running applications. |
| Volatile memory | Requires power to retain data; typical RAM is volatile. |
| Non-volatile storage | Retains data without power; SSDs and HDDs are examples. |
| SSD | Solid-state drive; persistent storage without moving mechanical parts. |
| NVMe | Non-Volatile Memory Express; storage protocol commonly used by PCIe SSDs. |
| Utilization | Fraction of a resource in use over a measurement interval. |
| Process | Running instance of a program. |
| Baseline | Reference measurement under defined conditions. |
| Bottleneck | Resource or component limiting workload performance. |
| Virtual machine (VM) | Software-defined guest computing environment. |
| vCPU | Virtual processor presented to a guest by a hypervisor. |
| Root cause analysis | Investigation to identify underlying causes rather than just symptoms. |
| Workaround | Temporary way to maintain service without resolving the underlying cause. |
| Remediation | Action addressing an identified problem or risk. |
| Problem scoping | Determine affected users, workloads, timing and recent changes. |

Practice: explain why 94% memory utilization warrants investigation but does not automatically justify a RAM upgrade. Explain why an updated spreadsheet can increase CPU demand without defective hardware. Distinguish guest specifications from host hardware. These are review prompts, not evidence of independent mastery.
