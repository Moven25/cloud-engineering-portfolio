# Workplace simulation protocol
Approved 2026-11-27. Planned training, not employment or production experience.

## Operating cadence
Integrate a brief simulated stand-up (yesterday, today, blockers) into training days, and weekly sprint planning, stakeholder meeting or design review into existing professional development time. Use a prioritized ticket backlog, acceptance criteria, dependencies and handoffs. Do not displace foundational lesson, flashcard or assessment routines. Introduce tools only when needed; no paid resources without approval.

## Progressive assignments
| Stage | Workplace exercise | Evidence |
|---|---|---|
| Foundations | Customer ticket, incomplete symptoms, escalation | Ticket, diagnosis, verification, handoff |
| Early IT | Competing tickets, inherited poorly documented systems | Priorities, inventory, runbook, change request |
| Networking/Linux | Unfamiliar fault, conflicting requirements | Hypothesis, tests, stakeholder clarification |
| Cloud | Inherited AWS environment, design review, simulated outage | Architecture, ADR, incident timeline, recovery tests |
| Automation | Read and modify existing code, branch, pull request, review | Diff, tests, review response, rollback |
| AI infrastructure | Model/API failure, data access or cost incident | Evaluation, monitoring, containment, recovery, cost analysis |
| Capstone | Sprint planning, team handoff, executive defense | Backlog, acceptance tests, runbook, presentation |

## Incident and change practice
Use isolated synthetic environments; define severity, impact, escalation, recovery objectives and authorized scope. Start untimed, then use realistic timeboxes after proficiency. Record observations, hypotheses, mitigation, verification, root cause when established, and prevention actions. Require approval before risky changes, backup and rollback plans, and evidence of recovery. Never introduce faults into real third-party systems.

## Assessment
Coach role-plays users, manager, reviewer and teammates; no claim of real team collaboration. Gradually remove hints. Permit official documentation in independent exercises; record assistance. Evaluate prioritization, technical accuracy, safe changes, communication, ownership, testing and handoff using existing rubric. Knowledge 85%, terminology 90%; employment readiness overall rubric remains separate. Repeat unfamiliar scenarios when gaps remain. Seek real peer review or authorized open-source contributions when feasible, without claiming they occurred.

## Portfolio and readiness
Map exercises to existing lab IDs, not additional formal assignments. Publish only sanitized verified artifacts, label simulations and guided work, keep scores private. Monthly employer skills review and 30-day readiness checks; apply to suitable IT or cloud roles when evidence supports it. Real production accountability, organizational context and human team experience remain limitations.
